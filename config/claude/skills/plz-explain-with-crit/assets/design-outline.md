# 設計判断を伝える HTML の構成案

読者が判断を追いやすい既定の流れとして使う。見出しを機械的に揃える規則ではない。

1. **目的・ゴールと提案の要約**: 何を解決し、どの判断を求めるかを先に示す。
2. **問題の構造と根拠**: ゴールを妨げる条件、現状との差、判断の根拠を示す。
3. **選択肢と採否理由**: 成立する案を同じ目的・範囲・制約の下で比べ、提案と判断待ちを示す。
4. **変更後の仕組みと影響範囲**: 採用案がどう働き、何に影響するかを図で示す。
5. **検証結果と未決判断**: ゴールをどう確かめたか、未検証事項と判断への影響を示す。

「選択肢と採否理由」には、議論 (crit の返信やチャット) で却下した案もすべて記録する。却下した範囲とユーザーが問題とした点を理由として残し、比較表に載らない粒度の判断も含める。却下した案と理由は完成時点の判断材料であり、改稿履歴ではない。

題材に応じて章を統合、省略、並べ替えできる。図を中心にし、判断に必要な説明だけを添える。空の章や、分析・作業・改稿の履歴は入れない。
