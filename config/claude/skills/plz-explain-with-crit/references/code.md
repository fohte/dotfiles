# 対象: PR / コミット範囲 / 既存ファイル

リポジトリにすでに存在するコードを対象にする場合。

## 準備と起動

対象リポジトリがローカルに無ければ先に用意する (owned org なら `ghq get -u`)。
**対象リポジトリのディレクトリで**起動する。

| 対象                    | 起動コマンド                  |
| ----------------------- | ----------------------------- |
| GitHub PR               | `crit --pr <num>`             |
| コミット範囲            | `crit --range <base>..<head>` |
| ファイル / ディレクトリ | `crit <path> [...]`           |

ブランチが対象なら引数なしの `crit` でもよいが、その場合 base branch の自動検出に依存する。
どの差分を見せたいかが決まっているなら `--range` で明示するほうが確実。

## 一次情報

- **該当ファイルを Read する。** diff の追加行だけ見て答えない。削除された側や周辺のコードを見ないと、変更の意味は分からない
- PR 全体の文脈が要るときは `gh pr diff <num> --repo <owner>/<repo>` を使う
- **「なぜこう書いてあるか」を聞かれたら、コミットメッセージと PR 本文に当たる。** そこに書かれた意図はコードから復元できない。無ければ `git log -S<識別子>` や `git blame` でその行が入ったコミットまで遡る
- 呼び出し元・呼び出し先まで辿ってから答える。その行だけ見て答えると役割を取り違える

## 注意

セッションを使い回していると、現在の diff から外れた行にコメントが付くことがある (crit 上で Outdated 表示)。
行番号が信用できないので、コメントの `anchor` から現在位置を引く (crit:crit-cli 参照)。
